# 第二大脑

这是主人的第二大脑，也是SuperHub 团队的唯一状态来源。一切都是纯文本，可以 grep、可以 git 回滚。

| 路径 | 内容 | 谁来写 |
|---|---|---|
| `AGENTS.md` | 宪法：我是谁、原则、隐私边界、幕僚团约定。DSH 会自动加载 | 主人 |
| `me.md` | 关于我：主人确认过的事实（身份、阶段、偏好）。也是导出给其他助手的来源 | 主人；幕僚只能经提案修改 |
| `goals.md` | 阶段目标 | 主人 |
| `staff/*.md` | 幕僚角色卡：职责、执行者、审查官 | 主人 |
| `rules.yaml` | 时钟规则（早报、复盘、每周整理）与允许修改的工作区 | 主人 |
| `people/` `lines/` | 人物卡、横向线 | 事实和互动由幕僚记录；判断（关系、影响力、立场、健康度）只有主人改 |
| `ledger/` `meetings/` | 承诺账本、会议 | 主人和幕僚 |
| `notes/` `decisions/` | 长期知识 | 主人；幕僚只能经提案修改 |
| `journal/` | 日志与随手记录 | 主人、接口人 |
| `proposals/` | 幕僚提出的修改，等主人批准 | 幕僚 |
| `work/T-xxxx/` | 每张工单的产出 | 幕僚 |
| `inbox/` | 随手丢进来的材料 | 主人 |
| `ops/` | 事件、工单、去向（机器状态，勿手改） | SuperHub |
| `ui/custom.json` | 作战台的界面定制（主题、版式、自定义面板） | 接口人，按你的要求 |

记忆规则：幕僚不直接改长期知识。想改的内容写成 `work/T-xxxx/proposal.md`，主人在作战台点"通过并执行提案"后才落地，每一步都有 git 记录。
