未完成的任务可能继续占用注意力。设计上，让交办有去处、过程有容器，给离开一件事留下明确的交接点。

Leroy · 2009 · 注意力残留 ↗

给回来的人保留线索

目标记忆模型讨论目标激活、干扰与提取线索。设计上，保留原话、当前进展与成果，帮助人重新接上原来的工作。

开始之前，你可能想知道。

SuperHub 是什么？

SuperHub 是基于 DeepSeek Harness 的个人 AI 工作空间。通过一个接口人交办，按项目配置幕僚与上下文，在工作区协作、从汇报接回决定。当前是 DSH Web 插件，并提供手机浏览器入口。

SuperHub 和 DS Bot、Personal Agent 有什么区别？

SuperHub 的优势在于多项目并行时，每个项目都能接着做，你也能按自己的节奏接回汇报。 一个工作区把同一项目的多场会话、多张工单、成员职责和交付放在一起。幕僚可以跨项目复用，项目上下文各自积累。你从统一入口接回各项目的汇报，再决定什么时候深入哪一件事。

例如，你正在整理客户访谈，产品接入检查突然失败。你要交出一项排查，拿到修复和验证方案后再决定是否改动。

DS Bot 围绕 Bot 和群聊组织协作。 在研发群交办，群管理员召集工程和验证 Bot，结果发回群里。这个群有自己的记忆和工作目录，也可以从任务页看后台进度。 DS Bot 功能说明 ↗

Personal Agent（以「搭档」为例）围绕一个助手和它接下的工单组织工作。 把排查交给搭档，它开单并在工单的会话和目录里执行。你从原交办入口接回结果，或从面板和日报回看。 「搭档」项目说明 ↗

SuperHub 围绕长期项目工作，汇报集中给你。 在「一句话交办」说清目标和改动边界，接口人把排查放进「产品研发」，由本区幕僚分工。

工作区上下文隔离，让项目可以续做。 今天有接入排查，明天可以另开会话做发布核对。做发布核对时，从研发工作区就能找到上次的报告、已做的验证和还待确认的决定。即使两边用同一位研究员，他在研发核对配置与验证依据，在访谈核对受访者原话。研发积累的本区经验留在研发。想把其中一条方法用到访谈时，可以只共享那段文字。

注意力管理，让你少为跟进切换项目。 方案交回时，你还在访谈里写提纲。「一句话交办」的红点留住未读汇报。你可以先写完这一段，再看接口人归纳的结论和待确认项。要决定是否改配置，从汇报进原工单核对依据。需要盘点几条主线时，回「今天」一起看各项目的交付。

幕僚是固定的几个角色吗？

你可以创建全局幕僚、邀请它加入工作区并设定本区职责，也可以创建工作区专属幕僚。专属幕僚可选由 DSH 模型（含具体模型与思考深度）、Codex 或 Claude Code 执行，也可以在群里直接让接口人加人或换执行方式。名称、职责和头像可调整，经验可以采纳、共享、撤回或重置。

待采纳的经验如果一直不点，会怎样？

有足够依据时，经验会自动生效。一次原始交付或真实测试可以支持限定条件下的事实。归纳出的做法需要两个独立工单印证。依据不足的建议会继续待采纳。你可以在「经验」或「成长记录」核对来源，查看自动采纳、更正或过期的理由。

工作区的上下文边界是什么？

工作区分别组织对话、项目职责与本区经验。通用做法可以复用，跨区经验可由你选择文字、接收人、用途与有效期。这里描述的是应用中的上下文组织和授权，不是独立账号或文件系统沙箱。

定时提醒会发到哪里？

对接口人说「工作日 9 点提醒我未关闭的工单」，它会建立一条定时安排，回执写明下一次时间和提醒位置。到点后提醒出现在「一句话交办」的对话里，配置推送地址时同时推送到手机。所有安排集中在「设置 → 定时安排」，可以查看、停用或删除。早报和晚报默认关闭，需要时再打开。

红点会只提醒必须立即处理的事吗？

目前红点表示接口人的未读回复、讨论回报和提醒。它提供集中回看的入口，不是紧急度分类，也不表示每项都要立刻处理。

怎样把已有 AI 经验带进来、再带出去？

把导入提示词发给常用助手，贴回它对你的了解，在 SuperHub 逐条核对、修改或采纳。导出时可以生成给 ChatGPT、Claude 的文字，或用于 Codex、Claude Code 的指令文件区块与会话背景。本机同步需由你配置；导出采用已确认的本人资料、协作约定与有效目标，标记为机密的内容会被过滤。

可以接入哪些执行工具？

DSH 模型成员可以与使用 Codex 或 Claude Code 的成员在工作区协作，工作区专属幕僚也能单独指定执行方式和模型。具体可用工具、模型和账号取决于你的运行环境与成员配置。

资料存在哪里？

工作资料保存在运行 SuperHub 的主机及你选择的资料目录中。调用模型时，相关内容按所用模型服务处理，不能把本地保存理解成全程离线。

能完全不干预地持续工作吗？

SuperHub 提供分工、进展、跟进和交付入口。实际推进取决于模型、工具与任务情况；缺少信息或需要决定时，仍要由你接话和确认。
